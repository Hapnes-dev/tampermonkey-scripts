   caps "A-Alarm" near 41 px. A rendered width is an estimate, and no
   rule may fail a panel on an estimate. The centring formula was kept;
   the tolerance became validator rule V-P08, a WARNING, never an error.

WHY THIS FILE CHANGES AT ALL
-----------------------------
AI-BRIEFING.txt is the output contract: what a valid panel JSON must
contain. It does that job well. Three defects are structural, not factual:

 1. THE PRECEDENCE RULE IS BURIED AND INCOMPLETE. "EVIDENCE PRIORITY" sits
    inside section 7a, so it reads as a ventilation rule. It is not - it
    governs every panel type. It also lists five ranks where seven are
    needed: it omits CLAUDE.md's panel-specific rules and this briefing
    itself, so an agent holding a supplied JSON, a production export and a
    briefing rule that disagree has no stated way to choose. This is the
    single highest-value change in the whole audit.

 2. MEASURED GEOMETRY IS STATED HERE AND ALSO IN TWO OTHER FILES, with no
    marker saying which copy wins. 7a-2 and 7a-4 print coordinates that
    also appear in CLAUDE.md section 17b and now in
    VENTILATION-GEOMETRY-CONTRACT.md. Three copies, no owner.

 3. THE FILE SAYS IT IS "SELF-CONTAINED" AND ALSO REQUIRES FOUR OTHER
    FILES. Both are half true, and the contradiction matters: an agent
    given only this briefing needs to know what it can still do.

The fix for 2 is NOT to delete the coordinates from here - that would break
the self-contained property that makes this file uploadable on its own. The
fix is to mark every duplicated measurement with its evidence id and a line
naming the contract as authoritative on conflict.

R2 - NEW SECTION 0 (insert immediately after R1, before section 1)
-------------------------------------------------------------------
This is the change the whole audit turns on. Insert verbatim:

  0. SOURCE PRECEDENCE (NORMATIVE - APPLIES TO EVERY PANEL TYPE)
  --------------------------------------------------------------
  When two sources disagree, the higher rank wins. Name the rank you used
  in your verification report.

    1. A panel JSON or screenshot supplied with the current task.
    2. A real production export of the same panel type
       (reference_data/*.json).
    3. Panel-specific rules in iwmac-designer-reference/CLAUDE.md.
    4. This briefing.
    5. PANEL-TYPE-GUIDE.md.
    6. DESIGN-OBJECT-CATALOG.md.
    7. Generic visual-design advice.

  DO NOT AVERAGE CONFLICTING COORDINATES. Use the highest-precedence
  source. Two anchors that disagree are two different panels, not one
  panel measured twice: splitting the difference produces a layout that
  matches neither and that no site will recognise.

  Three consequences that catch agents out:

  - A SIZE IN THE ALLOWLIST OR THE CATALOGUE IS A TOOLBOX DEFAULT, NOT A
    PLACEMENT. Rank 6 loses to rank 2. Seven objects in the ventilation
    references are placed at a size the catalogue does not list - the
    sidebar header is 60x25 in the palette and 250x20 on every real
    ventilation panel.

  - A SUPPLIED JSON OUTRANKS EVERY MEASUREMENT PRINTED IN THIS FILE.
    Its coordinates, sizes, z-indexes, object vocabulary and ordering are
    the template. The numbers in 7a were measured from a different
    export.

  - OBJECT COUNT IS NOT A QUALITY TARGET. Coverage of the required
    production roles is the target (7a-3 lists them). A panel is not
    better for having more objects, and not worse for having fewer - it
    is wrong when a required role is missing or a coordinate was
    invented.

  WHEN THE EVIDENCE DOES NOT EXIST, SAY SO. Do not guess a coordinate to
  fill a gap. Report what is missing and what you would need to measure
  it. A stated gap is recoverable; an invented number is not, because
  nothing downstream marks it as invented.

R9 - 7a-4 SIDEBAR, the centring correction (append)
----------------------------------------------------
Anchor: after the sidebar column description.

Append:

  COLUMN HEADINGS ARE NOT CENTRED BY GIVING THEM EQUAL WIDTHS.
  number_v3_label_11px_norm renders its text LEFT-ALIGNED inside its box,
  so two headings with identical posWidth over two identical columns
  still print off-centre. Position by rendered text width instead:

      posLeft = column_centre - rendered_text_width / 2

  Supply column: boxes x1260 w62, centre 1291 -> "Tilluft" at x1275
  w32. Extract column: boxes x1330 w62, centre 1361 -> "Avtrekk" at
  x1341 w40. DO NOT ASSUME EQUAL OBJECT WIDTHS IMPLY VISUALLY CENTRED
  TEXT. Contract section 7.2 gives the derivation; QA check C7 tests it
  to +/-2 px.


R10 - 7a-8 TAG CONVENTION (append)
-----------------------------------
Append:

  Write the real degree symbol: "RT401 °C". Never "gr C". The Insert flow
  reads UTF-8, production exports carry 13 degree-signed tags, the object
  catalogue itself prints "RT401 °C", and rendered tests confirm they
  survive. Mojibake comes from other transports (pasting through a
  terminal, an ISO-8859-1 page) - fix the transport, do not degrade the
  panel text.

  ONE OWNER PER PIECE OF TEXT. Do not add a standalone label when the
  equipment object already shows its tag; do not add a caption when the
  value object renders tag_text. Where a sidebar row label already names
  the signal, use a no-tag value object
  (number_v3_60px_dark_no_conn_no_tag). Two objects printing the same
  words is a defect, not redundancy.


R11 - 7a-9 BAD vs GOOD (rewrite)
---------------------------------
The existing list is sound but mixes measurable failures with taste. Split
it so each line is testable, and remove the two that use object count as a
proxy for quality.

Replacement:

  7a-9 HOW A VENT PANEL IS JUDGED. Every line here is testable; the test
  is in VENTILATION-QA-CHECKLIST.md.

  STRUCTURAL (Stage A) - the JSON is malformed or the vocabulary is wrong
   - an obj_id that is not in the catalogue (renders as a broken box)
   - counts that do not equal the array lengths
   - object names not sequential object_0..object_N
   - a panel.image_svg on a Ventilasjon panel
   - a missing or replaced background

  GEOMETRIC (Stage B) - the drawing does not read as ductwork
   - a duct run broken into segments that do not meet
   - a connector that stops short of the duct it should land on
   - a vertical crossover that does not reach both horizontal runs
   - a damper cleared by SHORTENING the duct instead of overlaying it
   - a cluster split: equipment moved without its value, output or alarm
   - a fan pointing against its run's airflow direction

  VISUAL (Stage C) - it parses and it renders, and it is still wrong
   - a value box overlapping a tag, another value, or a control
   - an alarm bell on top of the component instead of beside it
   - an LED outside its pill, or covering the numeric value
   - a heading that is off-centre because widths were equalised
   - "gr C" where the panel should print °C
   - a hover tooltip captured in the QA screenshot and mistaken for
     panel content

  LINKING (Stage D)
   - a source plant's driver_id, unit_id or link_tag carried into a demo
   - an invented driver id, unit id, file path or panel target
   - alias_text stripped during sanitization (it is what a human links
     by afterwards)

  NOT A DEFECT, and not to be "fixed":
   - a value box sitting on the duct it belongs to
   - a con_* connector edge landing ON its duct
   - a damper symbol overlaying a continuous duct column
   - an equipment body straddling the run it conditions
   - an object count lower or higher than the reference, when every
     required role is present and no coordinate was invented
