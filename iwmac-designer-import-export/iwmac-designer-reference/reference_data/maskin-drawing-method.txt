MASKIN (MACHINE PICTURE) DRAWING METHOD - Advansor CO2 cooling/freezer
=======================================================================
Distilled from "Advansor cooling/freezer machine drawing method v2"
(internal Word doc; project-specific identifiers omitted). This is the
reusable method for turning a technical refrigeration schematic (PDF
systemskjema) into the clean HMI-style machine picture used as an IWMAC
Designer panel background. Companion image: maskin-light-style-reference.png
(rendered 1:1 from maskin-light-template.ai, the same template family as
the light-background plant-9982 Maskin in real-vent/maskin examples).
Background colour is not fixed by this method - see section 6.

The PDF schematic is the technical source of truth; the drawing is a
simplified operator visualization. Do not reproduce every bend or
engineering annotation - preserve functional connections and labels.

1. HOW THE MACHINE WORKS (what the drawing must communicate)
-------------------------------------------------------------
CO2 booster system, two suction levels:
- MT compressors: medium-temperature loads (cooling).
- LT compressors: freezer loads; LT discharge lifts into the MT /
  intermediate side before final high-pressure compression.
Flow: consumers absorb heat -> suction gas returns (M-T Suct., L-T
Suct. lines) -> LT then MT compression -> oil separator removes oil
from hot discharge gas (oil reservoir stores it) -> gas cooler /
condenser rejects heat (fan block) -> optional HEAT RECOVERY branch
taps rejected heat (tap water) before/beside the gas cooler -> high-
pressure valve (Vhp) drops into the receiver -> receiver stores liquid
/ separates flash gas (Level %, Low-level, Prec bar) -> receiver valve
(Vrec) + liquid line feed the consumers again. Internal heat exchanger
sits in the bottom-right line section. PRV manifold / filter drier /
instrument manifolds exist in the PDF; show them only if operators
need them.

2. CANVAS LAYOUT DOCTRINE (1400 x 750, both real examples agree)
----------------------------------------------------------------
- MT compressor group: upper-left (labels MT1..MTn above each symbol).
- LT compressor group: lower-left (LT1..LTn) - visually LOWER because
  it is the separate, colder suction circuit.
- Oil separator ("Oil-sep."): on the discharge riser, top-left, close
  to the compressors.
- Gas cooler / condenser: top-right - white rectangle with a row of
  fan circles, the orange high-pressure run passes through it.
- Heat recovery heat exchanger: top-center branch off the discharge
  run (Shr sensors around it, V3hr valve).
- Receiver: right-of-center vertical rounded vessel with internal coil
  detail and a level bar; Level %, Low-level, Prec bar right next to it.
- High-pressure / receiver valves: at the orange-to-yellow transition
  right side (Vhp OD %) and near the receiver (Vrec OD % - some plants
  label it Vrec DD %); valve tag ALWAYS next to the valve symbol.
- Suction headers / consumer lines: parallel horizontal runs exiting
  bottom-right, each labeled at the line end: "Liq. consumer",
  "M-T Suct.", "L-T2 Suct.", "L-T Suct." - with small flow arrows.
- Information/status panel: full-height grey panel on the far right
  (Room Temperature, CO2 Alarm, Machine status pills, Heat recovery
  information box); navigation cross bottom-right corner.

3. CIRCUIT COLOURS = FUNCTION (one colour per circuit, per the PDF
   colour-code categories; keep each on its own layer)
------------------------------------------------------------------
  Circuit                      Colour        Layer name
  high pressure / discharge    orange        01_PIPE_HP_ORANGE
  receiver / liquid            yellow        02_PIPE_RECEIVER_YELLOW
  MT suction                   light cyan    03_PIPE_MT_SUCTION_CYAN
  LT suction                   blue          04_PIPE_LT_SUCTION_BLUE
Other layers: 00_BACKGROUND_LOCKED, 05_EQUIPMENT_COMPRESSORS,
06_EQUIPMENT_GASCOOLER, 07_EQUIPMENT_RECEIVER_HEAT_EXCHANGER,
08_VALVES_AND_TAGS, 09_INSTRUMENTS_AND_SENSORS, 10_VALUE_BOXES,
11_LABELS, 12_UI_INFORMATION_PANEL, 99_EXPORT_GUIDES_DO_NOT_EXPORT.
Pipes are simple ORTHOGONAL lines - no diagonals, no tiny bends.

4. SYMBOLS, VALUES AND TEXT RULES
---------------------------------
- One compressor symbol family, repeated with equal spacing for MT and
  LT; only label, pipe layer and value names change between copies.
- Fan = circle with blade glyph, repeated inside the cooler rectangle.
- One valve symbol style everywhere; V-xxx tag close to the valve.
- Live values: WHITE ROUNDED PILLS. In the IWMAC panel the pills are
  drawn EMPTY in the background and number objects render into them -
  never bake numbers in (existing production PNGs that show example
  text/states are mock states from the Illustrator master; when
  authoring image_svg, draw the pills empty).
- Setpoints / references: DARKER GREY pills, so operators can tell
  setpoint from measurement.
- Status colours: green = OK/running/enabled, red = alarm,
  grey = manual/inactive/reference.
- Instrument tags follow the PDF nomenclature: P/PI/PS pressure,
  T/TI/TS temperature, F flow; sensors seen on the real drawings:
  Pc, Tc, Sd, Ss, Sgc, Sc3, Shp, Shr2/3/4/8, Prec, Pgc, Suct C, SH K.
- Small arrows on pipes wherever direction matters (header exits,
  valve outlets).
- Text large enough for the HMI export - no tiny engineering notes.

5. Extending an existing Maskin compressor bank - the raster half
----------------------------------------------------------------------------
This section used to carry the whole compressor-bank editing procedure, JSON
included. It no longer does: one live owner per rule.

  The ordered procedure, step by step  -> MASKIN-AUTHORING-GUIDE.md #4a
  The rules with ids and evidence      -> MASKIN-GENERATION-CONTRACT.md #16
                                          (M-A01..M-A09, M-C01..M-C05)
  What must be true before delivery    -> MASKIN-QA-CHECKLIST.md stage C0
  The same rules as code               -> validate-maskin-panel.py --compare
  The failures these rules came from   -> MASKIN-AUTHORING-GUIDE.md,
                                          "Failure catalogue"

What stays here is the drawing technique, because that is what this file owns.
Five rules, all about pixels. None of them is checkable from a panel JSON: the
background is a base64 blob in the document, so no validator sees any of this.

R1. COMPOSITING MUST NOT MULTIPLY SOURCE ALPHA.
    Copy each source pixel's alpha verbatim. A mask is BINARY - a pixel is
    carried or it is not. A soft, feathered, blurred or opacity-scaled mask
    multiplies the source alpha, and then the entire clone - compressor
    symbol, both pipe branches, the static labels and the empty pills - comes
    out faded together. That uniformity is the tell: it reads as a rendering
    problem, but it is a compositing bug, and it is invisible in every JSON
    check that will be run afterwards.
    Equally: NEVER paste an opaque rectangular crop over pipes or unrelated
    art. Both errors are the same mistake - letting the mask decide alpha
    instead of the source.

R2. MEASURE EVERY SOURCE LINE INDEPENDENTLY.
    Centerline, RGBA colour, per-row alpha, thickness, anti-aliasing and
    junction geometry, per line, per drawing. The discharge header and the
    suction header of the SAME panel are not the same thickness. A number
    measured on one is evidence about that one only.

R3. REPRODUCE EVERY ROW THE SOURCE HAS.
    Including the partial-alpha anti-aliasing rows, with the source's own
    alpha values. A three-row line whose outer row is faint is a three-row
    line; delivering its two visible rows produces a thinner, harder pipe
    that visibly does not match the header it joins. Visual equality to the
    source outranks any generic two-pixel line-width rule.

R4. RESTORE HEADERS AND JUNCTIONS FROM THE SAMPLED SOURCE RASTER,
    then place the compressor housing above the branches. Junction pixels are
    part of the measured style, not cleanup detail. Inspect the background
    ALONE, at native size, before any object is placed on it: once the pills
    and status strips are on top, a gap at the junction cannot be seen.

R5. AFTER A FAILED ITERATION, RESTART FROM THE RETAINED ORIGINAL.
    Never repair the next attempt on top of an already damaged crop. Two
    compensating edits hide each other rather than reverting, and the damage
    stops being attributable to any single step.

Layer ownership is unchanged and absolute: image_data owns pipes, equipment,
static labels, pill and status artwork and the EMPTY value fields; dynamic
objects own live status and values. NEVER bake live text, state or numbers
into new artwork.

MASKED C3-TO-C4 WORKED EXAMPLE
Before: C1 is MT with status/capacity/VSD/runtime. C3 is the nearest
fixed-speed MT sibling with status/capacity/runtime. The measured C3-to-C4
vector is (+24, 0) in the 96 x 64 miniature fixture only; production edits
MUST remeasure their own exact pitch.

Background-only after: image_data points to raster-after.json; all three
object arrays are empty and all three declared counts remain zero. The changed
image_data is explicit regression evidence that this is a real image patch.

Full after, when parameter boxes were explicitly requested: preserve all seven
source objects exactly; append object_7..object_9 for C4 status, capacity and
runtime using placeholder driver_id, linked false, blank link/unit fields and
descriptive aliases. No VSD object is added. The background anchors and all
three dynamic-object centers use the same (+24, 0) translation.

Measured in that fixture, as an illustration of R2 and R3: the orange
horizontal header has three sampled rows with alpha 191 / 255 / 64, the cyan
header has two opaque rows, and the vertical branches have two opaque columns.
Two headers on one drawing, two different row counts - which is the whole point
of measuring each line separately. These values are example-specific and are
NEVER defaults; a production edit measures its own raster.

The masked derivative is in tests/fixtures/maskin-compressor-bank/. Its
one-pixel registration markers and magenta field anchors are test-only colours,
separate from the miniature art. Run the dependency-free regression with:
  python -m unittest tests.test_maskin_compressor_bank

5b. Removing equipment and rerouting a circuit - the raster technique
----------------------------------------------------------------------------
Same division of ownership as section 5: the ordered procedure is
MASKIN-AUTHORING-GUIDE.md #4b, the rules with ids and evidence are
MASKIN-GENERATION-CONTRACT.md #17 (M-A10..M-A19, M-C06, M-X01..M-X07), the
acceptance evidence is MASKIN-QA-CHECKLIST.md stage C0b, and the pixel checks
are maskin_raster_qa.py / maskin-visual-qa.py. What stays here is the
technique, because that is what this file owns. Five more rules, all about
pixels, none of them visible to any JSON check.

R6. AN ERASE MASK IS A SET OF SHAPES, NOT A RECTANGLE.
    Build the mask from the component's own outline, fill, internal detail,
    labels and connection pixels - then subtract every protected neighbour
    that touches it. A rectangle comfortably bigger than the equipment is
    comfortably bigger than the clearance to whatever is beside it, and on
    this drawing that is usually a vessel. Complex equipment symbols are
    ATOMIC: the receiver is body + rounded ends + outline + internal coil or
    divider + level bar + its labels + its connection pixels, and a receiver
    missing its left wall is not a receiver with a small defect, it is a
    different symbol. If the mask reaches a protected boundary, restore that
    whole component from the retained original by pixel copy. Redrawing it
    produces a new symbol that no longer matches its twins elsewhere on the
    panel.

R7. FLATTEN BY PIXEL CLASS, NEVER BY BRIGHTNESS.
    Four classes, and only one of them is background: fully transparent
    (alpha 0 - shows whatever the host puts behind it, which is how a picture
    asked for light arrives black), opaque source background (the canvas
    colour THIS drawing uses, sampled from a clean area of it), opaque black
    artwork (line work and glyph cores), and legitimately dark text, outlines
    and arrows. Flatten the confirmed background pixels to the sampled
    background colour and leave the other three alone. A global
    dark-pixels-to-light replacement takes the labels with it. Sample several
    blank points afterwards - main canvas AND the grey information panel -
    because one sample proves one pixel. And keep the colour conversion as its
    own pass: merged with an equipment removal, the small diff hides inside
    the large one.

R8. A NON-CONNECTED CROSSING IS DRAWN, NOT IMPLIED.
    Two orthogonal runs cannot both be continuous and disjoint in one raster
    layer - at the crossing, one is drawn over the other. The convention: the
    FOREGROUND circuit is carried over by a bypass (leg up, span across, leg
    back down, then the run continues), drawn entirely in that circuit's own
    measured colour, thickness and per-row alpha; the crossed circuit stays
    continuous, interrupted by the bypass span and by nothing else. No
    background gap, no dark residue, no junction dot. Size the jog so it reads
    at native size - a one or two pixel offset is noise, not a bypass. And the
    two circuits must touch nowhere else: contact away from the crossing
    window reads as a connection, which is the opposite of what the drawing is
    saying.

R9. RESTORE CONTINUITY FROM THE SOURCE, THEN CHECK IT MECHANICALLY.
    Clearing a corridor to make room for a new run cuts whatever else passed
    through it. Restore those runs from the retained original, with their own
    per-row alpha, before drawing anything new. Then check every junction the
    edit touched - not the one in the screenshot: both endpoints, the shared
    rectangle, and whether the OPAQUE cores overlap. A join where only the
    antialiasing rows touch reads as connected at a glance and is not. Finish
    with a connected-component search over the circuit's own pixels: the
    ledger proves each join, the components prove the route.

R10. DIFF AGAINST THE RETAINED ORIGINAL, IN SCOPES.
    The comparison is always with the retained original, never with the
    previous attempt - two compensating edits hide each other rather than
    reverting, and after three nothing is attributable. Changes outside the
    union of the documented edit masks must be zero. When a background-colour
    conversion was also requested, report its diff SEPARATELY from the local
    artwork diff and confirm the protected foreground artwork is unchanged in
    both; one combined number always hides the smaller change, and the artwork
    change is the smaller one.

6. BACKGROUND COLOUR + THE SHIPPED TEMPLATE
--------------------------------------------------
Background colour is a requirement of the job, not of this method:
- PRESERVE the background of a supplied production export. Change it
  only when the user explicitly asks for a background change.
- For NEW artwork, take the background colour from the user's
  requirement, or from the production reference chosen for the job.
- A dark background is not a defect on colour grounds alone, and an
  existing dark maskin does not have to be redrawn light.
The one rendered reference that ships with this kit is
maskin-light-style-reference.png - white/very light canvas, mid-grey
line work - rendered 1:1 from the Illustrator source
maskin-light-template.ai (Advansor 781 template). It is light because
that is the template that was captured, and it describes the committed
file rather than mandating a skin; most production maskin pictures in
the surveyed corpus are light for the same historical reason.

Everything else in this document applies at any background colour: the
layout doctrine, the circuit colour code as function (orange = HP /
discharge, yellow = receiver/liquid, cyan = MT suction, blue = LT
suction), the symbol family, the EMPTY value pills, the darker setpoint
pills, and rules R1-R5. On a dark background keep the line work and text
readable against it - the colour changes, the contrast requirement does
not.

FACTS READ OUT OF THE PRODUCTION .AI ITSELF:
- Artboard is exactly 1400 x 750 pt (1 px = 1 pt) - confirmed.
- The real layer structure is THREE layers with Norwegian names:
  "Maskinrom" (equipment + symbols + pills + text), "Ror" (pipes,
  spelled R-o-slash-r) and "Backround" (sic - production's own
  spelling; keep it when editing existing files). The 12-layer naming
  template in section 3 is the tidy recommendation for NEW files; the
  shipped template uses these three.
- Label variants seen across production: suction-group temperature row
  is "Po C" on the canonical template and "To C" on some plants;
  runtimes are "Runtime h"; the heat-recovery dark pills are
  "Hr Req %" + "Hr Ref" (older: "Consumer Ref %" + "Ref").
- Vrec is the receiver FLASH-GAS valve: it sits on the cyan
  suction-side line leaving the receiver's left side (gas bypass to MT
  suction) - NOT on the yellow liquid line.
- V3gc is drawn as a motorized 3-way valve glyph at the corner where
  the gas-cooler bypass rejoins; V3hr likewise at the HR heat
  exchanger; V3tw (tap water) exists on plants with a tap-water HR
  branch. The grey "Heat recovery information" box legend lists them:
  "V3hr = Hr active", "V3tw = Tw active", "V3gc = Gc-bypass active".
- The receiver is drawn double-walled: outer rounded vessel + inner
  rounded rectangle, coil at the bottom, level bar at the right.

7. WORKFLOW (PDF -> Illustrator -> PNG) + QUALITY CHECK
-------------------------------------------------------
1. From the PDF: list circuits (HP, receiver/liquid, MT suction, LT
   suction) and main components; decide what operators need.
2. Artboard = target HMI size (1400 x 750 px, 1 px = 1 pt); background
   layer locked; one layer per circuit/equipment class; save symbols
   (compressor, fan, valve, vessel, value pill, status pill).
3. Place large equipment first (layout doctrine above), then pipes as
   orthogonal runs coloured by function, then labels close to their
   equipment, then value pills on an aligned grid, then the UI panel.
4. Check: every pipe end has a destination or label; every copied
   block has correct MT/LT naming; valve/sensor tags match the PDF;
   contrast OK at 100% and at HMI screen size.
5. Export PNG at exact HMI resolution; store PNG + AI source + PDF
   revision together.

8. DIVISION OF LABOUR IN AN IWMAC PANEL (kit contract)
------------------------------------------------------
The background (image_svg / PNG) draws: enclosure, pipes, equipment
symbols, empty pills, static labels, the grey info panel frame.
The OBJECTS deliver every live element: numbers (number_v3_value_only
on the empty pills), status strips (V3_akpc_*), alarm banner
(V3_ok_alarm_nrm), Manuel/state pills, LEDs. See AI-BRIEFING section 8b
+ maskin-akpc-link-map.json for how those objects link to the AK-PC
pack controller.
