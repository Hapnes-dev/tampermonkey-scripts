MASKIN (MACHINE PICTURE) DRAWING METHOD - Advansor CO2 cooling/freezer
=======================================================================
Distilled from "Advansor cooling/freezer machine drawing method v2"
(internal Word doc; project-specific identifiers omitted). This is the
reusable method for turning a technical refrigeration schematic (PDF
systemskjema) into the clean HMI-style machine picture used as an IWMAC
Designer panel background. Companion image: maskin-dark-style-example.png
(the dark-background variant of the exact same template family as the
light-background plant-9982 Maskin in real-vent/maskin examples).

The PDF schematic is the technical source of truth; the drawing is a
simplified operator visualization. Do not reproduce every bend or
engineering annotation - preserve functional connections and labels.

1. HOW THE MACHINE WORKS (what the drawing must communicate)
-------------------------------------------------------------
CO2 booster system, two suction levels:
- MT compressors: medium-temperature loads (cooling).
- LT compressors: freezer loads; LT discharge lifts into the MT /
  intermediate side before final high-pressure compression.
Flow: consumers absorb heat -> suction gas returns (M-T Suct., L-T
Suct. lines) -> LT then MT compression -> oil separator removes oil
from hot discharge gas (oil reservoir stores it) -> gas cooler /
condenser rejects heat (fan block) -> optional HEAT RECOVERY branch
taps rejected heat (tap water) before/beside the gas cooler -> high-
pressure valve (Vhp) drops into the receiver -> receiver stores liquid
/ separates flash gas (Level %, Low-level, Prec bar) -> receiver valve
(Vrec) + liquid line feed the consumers again. Internal heat exchanger
sits in the bottom-right line section. PRV manifold / filter drier /
instrument manifolds exist in the PDF; show them only if operators
need them.

2. CANVAS LAYOUT DOCTRINE (1400 x 750, both real examples agree)
----------------------------------------------------------------
- MT compressor group: upper-left (labels MT1..MTn above each symbol).
- LT compressor group: lower-left (LT1..LTn) - visually LOWER because
  it is the separate, colder suction circuit.
- Oil separator ("Oil-sep."): on the discharge riser, top-left, close
  to the compressors.
- Gas cooler / condenser: top-right - white rectangle with a row of
  fan circles, the orange high-pressure run passes through it.
- Heat recovery heat exchanger: top-center branch off the discharge
  run (Shr sensors around it, V3hr valve).
- Receiver: right-of-center vertical rounded vessel with internal coil
  detail and a level bar; Level %, Low-level, Prec bar right next to it.
- High-pressure / receiver valves: at the orange-to-yellow transition
  right side (Vhp OD %) and near the receiver (Vrec OD % - some plants
  label it Vrec DD %); valve tag ALWAYS next to the valve symbol.
- Suction headers / consumer lines: parallel horizontal runs exiting
  bottom-right, each labeled at the line end: "Liq. consumer",
  "M-T Suct.", "L-T2 Suct.", "L-T Suct." - with small flow arrows.
- Information/status panel: full-height grey panel on the far right
  (Room Temperature, CO2 Alarm, Machine status pills, Heat recovery
  information box); navigation cross bottom-right corner.

3. CIRCUIT COLOURS = FUNCTION (one colour per circuit, per the PDF
   colour-code categories; keep each on its own layer)
------------------------------------------------------------------
  Circuit                      Colour        Layer name
  high pressure / discharge    orange        01_PIPE_HP_ORANGE
  receiver / liquid            yellow        02_PIPE_RECEIVER_YELLOW
  MT suction                   light cyan    03_PIPE_MT_SUCTION_CYAN
  LT suction                   blue          04_PIPE_LT_SUCTION_BLUE
Other layers: 00_BACKGROUND_LOCKED, 05_EQUIPMENT_COMPRESSORS,
06_EQUIPMENT_GASCOOLER, 07_EQUIPMENT_RECEIVER_HEAT_EXCHANGER,
08_VALVES_AND_TAGS, 09_INSTRUMENTS_AND_SENSORS, 10_VALUE_BOXES,
11_LABELS, 12_UI_INFORMATION_PANEL, 99_EXPORT_GUIDES_DO_NOT_EXPORT.
Pipes are simple ORTHOGONAL lines - no diagonals, no tiny bends.

4. SYMBOLS, VALUES AND TEXT RULES
---------------------------------
- One compressor symbol family, repeated with equal spacing for MT and
  LT; only label, pipe layer and value names change between copies.
- Fan = circle with blade glyph, repeated inside the cooler rectangle.
- One valve symbol style everywhere; V-xxx tag close to the valve.
- Live values: WHITE ROUNDED PILLS. In the IWMAC panel the pills are
  drawn EMPTY in the background and number objects render into them -
  never bake numbers in (existing production PNGs that show example
  text/states are mock states from the Illustrator master; when
  authoring image_svg, draw the pills empty).
- Setpoints / references: DARKER GREY pills, so operators can tell
  setpoint from measurement.
- Status colours: green = OK/running/enabled, red = alarm,
  grey = manual/inactive/reference.
- Instrument tags follow the PDF nomenclature: P/PI/PS pressure,
  T/TI/TS temperature, F flow; sensors seen on the real drawings:
  Pc, Tc, Sd, Ss, Sgc, Sc3, Shp, Shr2/3/4/8, Prec, Pgc, Suct C, SH K.
- Small arrows on pipes wherever direction matters (header exits,
  valve outlets).
- Text large enough for the HMI export - no tiny engineering notes.

5. Editing an existing Maskin compressor bank from an exported panel JSON
----------------------------------------------------------------------------
This procedure is the normative contract for extending an EXISTING Maskin
compressor bank. It applies to masked fixtures and production work, but the
fixture's marker colours and coordinates are test instrumentation only.
Production QA MUST sample the actual source pixels.

1. Decide the deliverable before editing. A background-only patch MUST change
   image_data, MUST declare counts of zero, and MUST keep single_objects,
   containers and graphics empty. An entire/full JSON MUST preserve the
   complete original panel document and every existing object array; ONLY
   explicitly requested objects may be appended. Insert JSON APPENDS objects.
   Insert an entire/full JSON only on an empty canvas unless duplication is
   intentional. A populated panel that needs artwork only gets the
   background-only patch.
2. Inspect the source target column before adding objects. Artwork does not
   imply live-object creation. Existing objects, including obj_id, name, id,
   size, position, zIndex, tag/link/unit fields, driver_id, linked state and
   alias_text, MUST remain exact unless the request explicitly authorizes a
   particular change.
3. Select the nearest sibling with the same operational role and treat its
   entire compressor column as one atomic visual template. The compressor,
   upper and lower branches, status artwork, static label, empty value pills
   and any explicitly requested dynamic objects travel as one coordinated
   pattern; NEVER copy only the compressor glyph.
4. Classify fixed-speed versus VSD before cloning. In the masked example C3 is
   the nearest fixed-speed MT sibling: it has status, capacity and runtime.
   C1 additionally has a VSD row. A new C4 matching C3 therefore gets exactly
   status, capacity and runtime when parameter objects were explicitly
   requested; it MUST NOT inherit C1's VSD object.
5. Measure one center-to-center translation vector and record it. Apply that
   same vector to the compressor symbol, both branches, status art, labels,
   empty pills and dynamic-object coordinates. Do not estimate separate
   offsets for separate layers.
6. Preserve layer ownership. Background image_data owns pipes, equipment,
   static labels, pill/status artwork and empty fields. Dynamic objects own
   live status and values and render above the background. NEVER bake live
   text, state or numbers into new artwork. Clone dynamic objects ONLY when
   the request asks for parameter boxes. New objects MUST use id and
   driver_id equal to the literal placeholder "driver_id", linked "false",
   blank unit_id, unit_ref, link_name, link_tag and sub_group, plus a
   descriptive alias_text. NEVER invent a driver ID.
7. Composite with source alpha or a mask containing only intended foreground
   pixels. NEVER paste an opaque rectangular crop over pipes or unrelated
   art. Restore continuous headers from the exact sampled source raster, then
   place the compressor housing above the branches. Junction pixels are part
   of the measured style, not cleanup detail.
8. Remeasure every source independently: centerline, RGBA colour, alpha,
   thickness, anti-aliasing and junction geometry. In the miniature worked
   fixture the orange horizontal header has three sampled rows with alpha
   191 / 255 / 64, the cyan header has two opaque rows, and vertical branches
   have two opaque columns. These values are example-specific, NEVER defaults.
   Visual equality to the source outranks a generic two-pixel line-width rule.
9. Reparse and validate JSON, declared counts, sequential object_N names, the
   exact source/output object diff and every protected existing field. Then
   render the full panel, a zoomed compressor-bank crop and the background
   WITH its dynamic-object overlay. A background-only preview cannot prove
   dynamic overlay alignment. Do not claim correctness without exact raster
   comparison and overlay QA.
10. After any failed editing iteration, discard that derivative and restart
    from the retained original export. Never repair the next attempt on top
    of an already damaged crop, shifted object set or altered metadata.

PRE-EDIT DECISION CHECKLIST
[ ] Retain an untouched original source export.
[ ] Confirm background-only patch versus entire/full JSON.
[ ] Confirm that Insert JSON appends and whether the target canvas is empty.
[ ] Inspect the target column for existing objects before creating any.
[ ] Classify the nearest sibling's role and fixed-speed/VSD status.
[ ] Measure exact center-to-center pitch; record one translation vector.

COMPRESSOR-BANK EDITING CHECKLIST
[ ] Clone the nearest role-matching sibling as one atomic column.
[ ] Reuse one vector for art, upper/lower branches, labels, pills and objects.
[ ] Keep pipes/equipment/static labels/empty fields in the background.
[ ] Keep live status and values in dynamic objects; do not bake live text.
[ ] Use an alpha-safe foreground mask/composite, never an opaque crop.
[ ] Restore headers and junctions from sampled source raster before housing.
[ ] Clone optional dynamic objects only when the request explicitly asks.
[ ] Use placeholder driver_id, linked false and blank link/unit fields.

POST-EDIT JSON INTEGRITY CHECKLIST
[ ] Reparse the output JSON.
[ ] Match declared counts to single_objects, containers and graphics lengths.
[ ] Verify sequential object_0..object_N names and no duplicate records.
[ ] List the exact source/output object diff: changed, added and removed.
[ ] Protect existing driver_id, unit_id, linked, alias, type and position.
[ ] Confirm a full JSON preserves all other source metadata and arrays.
[ ] Confirm a background-only patch has zero counts and three empty arrays.

POST-EDIT PIXEL/RASTER QA CHECKLIST
[ ] Compare pipe continuity, centerline, colour and measured thickness.
[ ] Compare alpha and anti-aliasing row/column patterns exactly.
[ ] Inspect every orthogonal junction and housing-over-branch edge.
[ ] Derive compressor centers from pixels and verify equal measured pitch.
[ ] Render and compare the full panel at its actual HMI size.
[ ] Render and compare a zoomed compressor-bank crop.
[ ] Render the background and dynamic objects together for overlay alignment.

MASKED C3-TO-C4 WORKED EXAMPLE
Before: C1 is MT with status/capacity/VSD/runtime. C3 is the nearest
fixed-speed MT sibling with status/capacity/runtime. The measured C3-to-C4
vector is (+24, 0) in the 96 x 64 miniature fixture only; production edits
MUST remeasure their own exact pitch.

Background-only after: image_data points to raster-after.json; all three
object arrays are empty and all three declared counts remain zero. The changed
image_data is explicit regression evidence that this is a real image patch.

Full after, when parameter boxes were explicitly requested: preserve all seven
source objects exactly; append object_7..object_9 for C4 status, capacity and
runtime using placeholder driver_id, linked false, blank link/unit fields and
descriptive aliases. No VSD object is added. The background anchors and all
three dynamic-object centers use the same (+24, 0) translation.

The masked derivative is in tests/fixtures/maskin-compressor-bank/. Its
one-pixel registration markers and magenta field anchors are test-only colours,
separate from the miniature art. Run the dependency-free regression with:
  python -m unittest tests/test_maskin_compressor_bank.py -v

FAILED-ITERATION LESSONS
- Adding objects before inspecting the target can duplicate existing controls.
- Returning a patch when full JSON was requested loses the requested document.
- Returning full JSON to a populated panel needing artwork only duplicates
  objects because Insert JSON appends.
- Copying a compressor without its full column breaks branches and field grid.
- Cloning the wrong sibling imports role-specific rows such as C1's VSD.
- An opaque crop hides continuous pipes and unrelated source pixels.
- A nominal two-pixel line can differ from the measured raster's alpha/style.
- A background-only preview says nothing about dynamic overlay alignment.
- Correctness cannot be claimed without exact full, zoomed and overlay
  comparison against the source pattern.

SUCCESSFUL SEQUENCE
Restart from the original export; classify background-only versus full output;
inspect the target and clone the nearest role match atomically; clone dynamic
objects only when requested; record and reuse one measured vector; composite
with an alpha-safe mask; restore exact sampled headers, branches and junctions;
then validate counts, the exact object diff, protected fields, raster style,
pitch and the combined background/object overlay.

6. LIGHT vs DARK VARIANT + THE CANONICAL TEMPLATE
--------------------------------------------------
The SAME template family ships in two skins:
- LIGHT: white/very light canvas, mid-grey line work - THE NORMAL LOOK
  ("how most maskin pictures should look"). Canonical reference in this
  kit: maskin-light-style-reference.png, rendered 1:1 from the actual
  Illustrator source maskin-light-template.ai (Advansor 781 template).
- DARK: near-black canvas, same layout, same circuit colours, brighter
  pill outlines (see maskin-dark-style-example.png).
Match the plant's existing maskin. The kit's general "never cover the
canvas in dark colors" rule applies to vent/overview panels - a maskin
drawn in the dark variant is the sanctioned exception.

FACTS READ OUT OF THE PRODUCTION .AI ITSELF:
- Artboard is exactly 1400 x 750 pt (1 px = 1 pt) - confirmed.
- The real layer structure is THREE layers with Norwegian names:
  "Maskinrom" (equipment + symbols + pills + text), "Ror" (pipes,
  spelled R-o-slash-r) and "Backround" (sic - production's own
  spelling; keep it when editing existing files). The 12-layer naming
  template in section 3 is the tidy recommendation for NEW files; the
  shipped template uses these three.
- Label variants seen across production: suction-group temperature row
  is "Po C" on the canonical template and "To C" on some plants;
  runtimes are "Runtime h"; the heat-recovery dark pills are
  "Hr Req %" + "Hr Ref" (older: "Consumer Ref %" + "Ref").
- Vrec is the receiver FLASH-GAS valve: it sits on the cyan
  suction-side line leaving the receiver's left side (gas bypass to MT
  suction) - NOT on the yellow liquid line.
- V3gc is drawn as a motorized 3-way valve glyph at the corner where
  the gas-cooler bypass rejoins; V3hr likewise at the HR heat
  exchanger; V3tw (tap water) exists on plants with a tap-water HR
  branch. The grey "Heat recovery information" box legend lists them:
  "V3hr = Hr active", "V3tw = Tw active", "V3gc = Gc-bypass active".
- The receiver is drawn double-walled: outer rounded vessel + inner
  rounded rectangle, coil at the bottom, level bar at the right.

7. WORKFLOW (PDF -> Illustrator -> PNG) + QUALITY CHECK
-------------------------------------------------------
1. From the PDF: list circuits (HP, receiver/liquid, MT suction, LT
   suction) and main components; decide what operators need.
2. Artboard = target HMI size (1400 x 750 px, 1 px = 1 pt); background
   layer locked; one layer per circuit/equipment class; save symbols
   (compressor, fan, valve, vessel, value pill, status pill).
3. Place large equipment first (layout doctrine above), then pipes as
   orthogonal runs coloured by function, then labels close to their
   equipment, then value pills on an aligned grid, then the UI panel.
4. Check: every pipe end has a destination or label; every copied
   block has correct MT/LT naming; valve/sensor tags match the PDF;
   contrast OK at 100% and at HMI screen size.
5. Export PNG at exact HMI resolution; store PNG + AI source + PDF
   revision together.

8. DIVISION OF LABOUR IN AN IWMAC PANEL (kit contract)
------------------------------------------------------
The background (image_svg / PNG) draws: enclosure, pipes, equipment
symbols, empty pills, static labels, the grey info panel frame.
The OBJECTS deliver every live element: numbers (number_v3_value_only
on the empty pills), status strips (V3_akpc_*), alarm banner
(V3_ok_alarm_nrm), Manuel/state pills, LEDs. See AI-BRIEFING section 8b
+ maskin-akpc-link-map.json for how those objects link to the AK-PC
pack controller.
