# IWMAC Designer — object catalog

Every object the designer toolbox can place: **797 distinct `obj_id`s** across 11 menu categories, each with what it is, what it draws, whether it can carry a value, and how often the real fleet actually uses it (266 compiled production panels).

Generated by [build-object-catalog.py](build-object-catalog.py) from `reference_data/all-design-objects.json` (palette), `reference_data/controls-registry.json` (render definitions) and the fleet surveys. Machine-readable twin: [reference_data/design-object-catalog.json](reference_data/design-object-catalog.json). **Do not hand-edit either file — re-run the script.**

## Rules

1. **Only these ids exist.** An `obj_id` that is not in this catalog does not render — the designer draws nothing. Never invent one, never guess a plural or a size variant.
2. **Copy the id verbatim**, including case and underscores.
3. **`Link` = can carry a `driver_id`.** `Link: no` objects are decoration or navigation — giving them a driver does nothing.
4. **`Tag` = the object shows `tag_text`** (the instrument code such as `RT401 °C`). Objects with `Tag: no` show nothing but their own graphic.
5. **`W×H` is the placement size in pixels** on the 1400×750 canvas. Pipe/duct pieces are meant to be stretched along their run (`posWidth`); symbols are not.
6. **`Production use` is evidence, not advice** — placements counted in the survey. `—` means the fleet never places it; prefer a used object when one fits.
