CORE FACT: VV has NO expression language, NO steps, NO script. Every operation (compare, AND, alarm, write) is a BLOCK; every data flow is a WIRE between numeric pins. If you are writing an expression string like "a && b > c", stop and convert it to blocks + wires.

OUTPUT FILE (exact shape, pure JSON, no comments, no trailing commas):
{"format":"vv-fbx-sketch","version":1,"exported_at":"<ISO8601>","source_plant_id":null,"source_sketch_id":null,"name":"<short name>","block_count":N,"connection_count":M,"sketch":{"mode":"function","require_plant_revision":0,"blocks":[...],"connections":[...],"groups":[]}}

BLOCK object — exactly these fields:
{"id":0,"type":"BIGGERTHAN","func":"biggerthan","compile_type":"function","data":null,"override":{},"runtime":{},"properties":{},"output_type":"boolean","x":260,"y":110}
- id: INTEGER, unique (0,1,2,...). Never a string.
- type: UPPERCASE key from the allowlist below ONLY.
- func: copied verbatim per type below. Never omit.
- Canvas label goes in override.alias_text. There is no "name"/"label"/"config" field.
- override/runtime/properties are BLOCK-level siblings of data — never inside data.
- x/y numeric: sources x=40, logic x=260-500, outputs x=700; parallel branches 150px apart in y.

CONNECTION object — exactly:
{"source":{"id":0,"put":0},"target":{"id":2,"put":0}}
source = block whose OUTPUT the wire leaves, target = block whose INPUT it enters, put = 0-based pin index. No "from"/"to"/"block"/"pin"/named pins. Outputs may fan out; each input takes EXACTLY ONE wire. Wire every non-optional input of every block you place.

BLOCK ALLOWLIST (type | func | compile_type | data):
- PARAMV | paramv | input | {"driver_ids":["<FULL_ID>"]} — reads a plant parameter. NON-EMPTY array of full driver ids like "5440_AK3_AKC_0_1_0_0_2576". Unknown id? Use data:null + override.alias_text "TODO bind: <what>". NEVER invent ids. A unit address like "000:001" is a UNIT, not a parameter.
- CONST | const | input | {"alias_text":"..","type":"integer|float|boolean|string","initial_value":X,"mode":"single","eng_unit":"..","readonly":false} (+"precision":"%.1f" only for float)
- CALENDAR | calendar_value | input | {"calendar":"<id>","offset":0,"post_offset":0} or null (TODO bind)
- BIGGERTHAN biggerthan / BIGGERTHANOREQUAL biggerthanorequal / SMALLERTHAN smallerthan / SMALLERTHANOREQUAL smallerthanorequal / LIKE like (equality) / UNLIKE unlike | function | data null, 2 inputs, output boolean
- COMP_AND comp_and / COMP_OR comp_or | function | null | 2+ boolean inputs; INVERT invert = NOT (1 input)
- ADD add / SUBTRACT subtract / MULTIPLY multiply / DIVIDE divide / MOD mod / AVERAGE average / MIN comp_min / MAX comp_max / DIFF diff | function | null | 2 inputs, output float; ABSOLUTE absolute (1 input)
- DELAY_VARIABLE | alarm_multi_delay | function | null — debounce: put0 = value, put1 = CONST seconds (REQUIRED)
- LATCH | latch.run | function | null — put0 set, put1 reset
- PULSE_COUNT | pulse_count | function | {"block_func_args":{"periode":"day","type":"flank_rising_edge","periode_amount":1}} — periode: sec|min|hour|day|week|month|year; type: over_or_equal_value|absolute_value|flank_rising_edge|flank_falling_edge|flank_changing_edge (native edge counting — key is "type", NOT "mode"). put0 = signal, put1 = CONST level (REQUIRED, must be CONST). Count resets each period; no "never".
- PERIODE_VALUE | counter_limit.run | function | {"block_func_args":{"mode":"alarm|value","periode":"day","period_amount":1}}; AVG_IN_PERIOD | avg_in_period | {"block_func_args":{"period":"min","period_amount":5}} — copy inner keys exactly per type (periode/period spelling differences ARE the contract)
- SELECTOR | selector | function | null — put0 boolean, put1 value-if-true, put2 value-if-false (use CONSTs)
- FORMULA | formula | function | {"formula":"inp0*1.8+32","output_type":"float","title":"..","precision":"%.1f"} — only inp0..inpN-1 variables; + - * / % ^, ?:, and/or, min max abs round floor ceil sqrt pow sin cos log log10 exp fmod pi() random() time() date('W'…) intval floatval idate substr strpos stripos strtotime; null ok in ?:; `state` = own previous output (hysteresis). No if(){}, no pi/e constants.
- ALARM | alarm | output | {"alias_text":"<alarm text>","pri":"a|b|c","alarm_type":"general|system","alarm_destination":"general|ew|cw"} — ONLY a/b/c exist (a most severe). No "severity"/"message"/"priority".
- VIRTUALOUT | virtualout | output | {"alias_text":"..","type":"integer|float|boolean","engineering":{"unit":".."}} — safe stored value; default output block.
- WRITETOUNIT | set_unit_value | function | {"force_write":false,"delay":0,"limit_count":false,"count":1,"driver_ids":["<FULL_ID>"]} — REAL HARDWARE WRITE. Only when explicitly requested with a confirmed target parameter; otherwise use VIRTUALOUT.
- TOGGLE_INTERVAL | toggle_interval.run | function | {"block_func_args":{"interval":"sec|min|hour|day|week|month|year","offset":0}} — symmetric square wave (flips each interval boundary; offset in whole seconds). NO duty/duration field: "X h every N days" is NOT expressible — use a plant CALENDAR instead.
- TAGVALUE: only feeds process blocks — for normal reads always use PARAMV.

THESE BLOCKS DO NOT EXIST (translate): EQUAL→LIKE, GREATERTHAN→BIGGERTHAN, LESSTHAN→SMALLERTHAN, AND→COMP_AND, OR→COMP_OR, NOT→INVERT, WRITE/WRITEOUTUNIT/DIGITAL_OUTPUT→WRITETOUNIT, DIGITAL_INPUT/ANALOG_INPUT/READ/SENSOR→PARAMV, CONSTANT→CONST, TIMER→DELAY_VARIABLE, COUNTER→PULSE_COUNT, SR_LATCH→LATCH. RISING_EDGE/TOGGLE/FLIPFLOP have no block: rising-edge = PULSE_COUNT type flank_rising_edge; toggle-per-edge = PULSE_COUNT(flank_rising_edge) → MOD ← CONST(2).

RECIPES:
- Threshold alarm w/ persistence: PARAMV → BIGGERTHAN ← CONST(limit) → [COMP_AND ← CALENDAR] → DELAY_VARIABLE ← CONST(seconds) → ALARM
- Toggle on rising edge: PARAMV → PULSE_COUNT(flank_rising_edge) ← CONST(1) → MOD ← CONST(2) → VIRTUALOUT
- Hysteresis: comparator(high) → LATCH.set; comparator(low) → LATCH.reset
- Setpoint by condition: condition → SELECTOR ← two CONSTs → VIRTUALOUT
